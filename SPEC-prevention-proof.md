# Spec: Disasters Prevented

## Objective

Add persuasive but honest prevention examples without unverified real-world attribution.

## Commands

`npm test`, `npm run lint`, `npm run typecheck`, `npm run registry:build`.

## Project Structure

A landing section composes static fictional scenarios.

## Code Style

Use clearly marked fictional scenario labels, not fabricated case-study metrics.

## Testing Strategy

Assert fictional disclosure and absence of company names in the section.

## Boundaries

- Always: present Bollard as a contributor, never a single cause.
- Ask first: naming a real company or incident.
- Never: claim unverified outcomes.

## Success Criteria

- Homepage includes a “Disasters Prevented” section using generic, clearly fictional scenarios only.

## Open Questions

No real incidents will be researched because fictional scenarios fully meet the requested constraint.
